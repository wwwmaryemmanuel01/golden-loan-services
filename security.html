20.7

Content Security Policy, deliberately limited

Shipped directive setobject-src 'none'; base-uri 'self'; form-action 'self'
Why only theseThe portal is inline-styled and inline-scripted, and no browser is available here to test a stricter policy safely
What it blocksPlugin/embed content, <base> hijacking, and forms posting to another origin
What it does not blockInline script injection — that needs a nonce or hash build, and a real browser test
Tightening itMove to a header at a proxy, then add script-src with hashes and test every page
A strict policy added without a browser test would either break the portal or give false assurance. This is the honest middle: real, verifiable restrictions that cannot alter rendering.

21.1

Server-side validation of uploads

specified
CheckRuleWhere it must run

Size10 MB per file, 5 files per requestServer, before buffering
DimensionsImages at least 200×200, no decompression bombsScanner
FilenameDiscarded; a generated id is used insteadServer
21.2

Filenames and browser MIME types are not trusted

A browser-supplied Content-Type and a filename extension are both attacker-controlled. The type is decided by inspecting the file signature on the server; the original name is kept only as a display string, never as a path.
Stored nameA random UUID plus an extension decided by the server
Display nameEscaped, length-capped, never used to build a path
Path traversalRejected: any name containing .. or / is refused
21.3

Malware scanning

Where it would runA scanning service called from the upload handler, or an isolated worker
What it seesThe bytes, in a private staging bucket — never the public bucket
On a hitThe object is quarantined, the uploader is told the file was rejected, an alert is raised
On a clean resultThe object is promoted to its final private location
StateNot configured no upload path and no scanner exist in this build
Until a scanner is wired in, the honest statement is that no file is scanned. This page will not claim otherwise.
21.4

Quarantine until scanning finishes

Staging bucketPrivate, no read policy for customers, auto-expiry on unscanned objects
DurationUntil the scanner answers, or 24 hours
Timeout behaviourFail closed — an unscanned object is never promoted
VisibilityThe uploader sees “checking”, not a download link
