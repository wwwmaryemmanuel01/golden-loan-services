2.3

The four kinds of card

  • Corporate — the company's own cards: the main account, branches and settlement. Two signatures above MK 1,000,000.
  • Staff purchase — issued to a named officer for approved purchases; the line manager approves every claim afterwards.
  • Fuel — whitelisted to fuel stations only, odometer recorded per fill, capped per fill and per month.
  • Virtual — number-only cards for online services, one service per card so a leak is contained and traceable.
2.4

The states a card moves through

  • Applied — requested, screening against the KYC and the card policy.
  • Issued — the envelope or the virtual number has arrived; waiting for activation.
  • Active — linked by its linking code and in use.
  • Blocked — held by us or the issuer; no new movements until it clears.
  • Replacement — a reissue in flight; the old reference stays for the history.
  • Expired — past its expiry; hotlisted and kept for the audit trail.

Card Linking Codes

The GLSVC pairing codes that connect a VISA card to the platform — issue, track and retire them here

single-use
3.1

How the linking code pairs a card

A linking code is how the platform and a VISA card are introduced. The code is generated here, shared with the cardholder through the secure channel, and entered once together with the card details — in this module or in Salaries · Payment Processing. The moment it is used, the code is retired and a fresh one is needed for the next card. Only the last four digits of the card are ever stored.

5.2

The first-use rules

  • A card is issued but not live until it is activated with the linking code and the OTP.
  • The first transaction must be a small one — the issuer runs it as a verification hold (MK 1 typical).
  • Virtual cards activate instantly but stay online-only; ATM use is impossible by design.
  • Fuel cards activate against the station whitelist; any other merchant is declined at the terminal.
  • If the OTP fails three times the card is held for the branch — identity is checked in person.

Verification Desk

Every card is proven before it is trusted — checksum, BIN, expiry, duplicates and the storage rule

VISA · Luhn · BIN
14.1

Run the verification checks

5 checks
!Luhn checksum · The modulus-10 test every VISA number must pass — run it on demandReady
!BIN range · The first digits identify the scheme and the issuer bankReady
!Expiry window · The card must be inside its MM/YY lifeReady
!Duplicate guard · The last four + issuer must not already sit on the registerReady
!Storage rule · Only the last four may be written anywhere — full numbers are refusedReady
14.2

What each check proves

  • Luhn — the typed digits satisfy the ISO checksum; a typo or a invented number is refused instantly.
  • BIN — the number starts 4 (VISA) and the issuer bank matches the card's stated sponsor.
  • Expiry — the card is alive; an expired card can be linked only as a historical record, never to pay.
  • Duplicate — the same plastic cannot be linked twice, even under a fresh linking code.
  • Storage — the pairing writes last four + expiry + holder. Nothing else. Ever.
14.3

The storage rule, in plain words

A full card number exists only while it is being typed. The moment the platform keeps anything, it keeps the last four digits, the expiry and the holder name — enough to recognise the card on a statement, never enough to spend on it. The CVV is not even held in memory.
